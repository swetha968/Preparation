The Circuit Breaker Pattern is used to prevent system failures by stopping repeated calls to a failing service. The Circuit Breaker Pattern is used to prevent system failures by stopping repeated calls to a failing service.

State                           Description
Closed (Normal State) -         Requests are allowed as usual. If failures exceed the threshold, it moves to Open.
Open (Failure Detected)         No requests are sent to the failing service. Instead, an error response or fallback is returned.
Half-Open (Testing Recovery)    A few test requests are sent. If they succeed, the circuit moves back to Closed. Otherwise, it stays Open.

8. What is the difference between the merge and remove method and detach methods

merge(entity):

Merges the state of a detached entity into the current persistence context.
If the entity is not already managed, it will become managed.
The state of the entity is copied to a managed entity, and an update statement is generated for it.


remove(entity):

Transitions an entity from the persistent state to the removed state.
The entity becomes managed and marked for deletion, and a delete statement is generated for it.

10. How JPQL query works?

JPQL stands for Java Persistence Query Language. It is a platform-independent query language that works on entity objects rather than directly on database tables. JPQL is similar to SQL, but the main difference is that it works on entity classes and their attributes, not directly on database tables or columns.

JPQL is Java Persistence Query Language defined in JPA specification. It is used to create queries against entities to store in a relational database.     JPQL is developed based on SQL syntax. But it wont affect the database directly.

14. What is inversion of control and how ioc works?

Spring IoC (Inversion of Control) Container is the core of the Spring Framework. It creates objects (beans), configures them, injects dependencies, and manages their life cycles. The container uses Dependency Injection (DI) to manage application components. It retrieves object configuration from XML files, Java-based configuration, annotations, or POJOs. Since the Spring IoC container, not the developer, controls the object lifecycle and dependency management, this concept is called Inversion of Control (IoC).

Spring IoC Container
The Spring IoC Container is the core of the Spring Framework. It is responsible for managing the lifecycle of beans and their dependencies.

There are two types of IoC containers in Spring:

BeanFactory 
ApplicationContext 
1. BeanFactory
The BeanFactory is the most basic version of the IoC container.
It provides basic support for dependency injection and bean lifecycle management.
It is suitable for lightweight applications where advanced features are not required.

2. ApplicationContext
The ApplicationContext is an advancement of the BeanFactory and provides additional features like event propagation, internationalization, and more.
It is the preferred choice for most Spring applications due to its advanced capabilities.

Key Features of IoC Container
The key features of IoC Container are listed below

Dependency Injection: Automatically injects dependencies into our classes.
Lifecycle Management: Manages the lifecycle of beans, including instantiation, initialization, and deletion.
Configuration Flexibility: Supports both XML-based and annotation-based configurations.
Loose Coupling: Promotes loose coupling by decoupling the implementation of objects from their usage.

17. @springbootApplication  --> 

The @SpringBootApplication annotation in Spring Boot is a meta-annotation that simplifies application setup by combining three other annotations: @Configuration, @EnableAutoConfiguration, and @ComponentScan. It effectively enables auto-configuration, scans for components in the specified package, and allows for defining custom beans. 
Here's a more detailed breakdown:
@Configuration: Indicates that the class provides configuration for the application. 
@EnableAutoConfiguration: Enables Spring Boot's auto-configuration mechanism, which automatically configures the application based on the libraries on the classpath. 
@ComponentScan: Instructs Spring to scan the specified package (and sub-packages) for annotated components like @Component, @Service, @Repository, etc

19. what is the difference between jpa respoistory and curd repository

CRUD Repository:  
There is an interface available in Spring Boot named as CrudRepository that contains methods for CRUD operations. It provides generic Crud operation on a repository. It is defined in the package org.springframework.data.repository and It extends the Spring Data Repository interface. If someone wants to use CrudRepository in the spring boot application he/she has to create an interface and extend the CrudRepository interface. 

Syntax: 
public interface CrudRepository<T, ID> extends Repository<T, ID>

T: Domain type that repository manages (Generally the Entity/Model class name)
ID: Type of the id of the entity that repository manages (Generally the wrapper class of your @Id that is created inside the Entity/Model class)

public interface DepartmentRepository extends CrudRepository<Department, Long> {}

JpaRepository :
JpaRepository is a JPA (Java Persistence API) specific extension of Repository. It contains the full API of CrudRepository and PagingAndSortingRepository. So it contains API for basic CRUD operations and also API for pagination and sorting. 

Syntax:

public interface JpaRepository<T,ID> extends PagingAndSortingRepository<T,ID>, QueryByExampleExecutor<T>

Where:

T: Domain type that repository manages (Generally the Entity/Model class name)
ID: Type of the id of the entity that repository manages (Generally the wrapper class of your @Id that is created inside the Entity/Model class)
Example:

public interface DepartmentRepository extends JpaRepository<Department, Long> {}

21. How two microservices communicate with each other?

Microservices primarily communicate with each other using either synchronous or asynchronous methods. Synchronous communication involves a service calling another and waiting for a response, often using protocols like HTTP or gRPC. Asynchronous communication, on the other hand, uses message brokers where a service sends a message without waiting for a response, and other services process the message independently. 
Synchronous Communication:
HTTP/HTTPS:
A common method where a service sends an HTTP request to another, and the server processes the request and returns a response. 
gRPC:
A high-performance, open-source framework that uses Protocol Buffers for serialization, providing a more efficient communication channel than REST. 
REST APIs:
A standard way for services to interact, using HTTP methods like GET, POST, PUT, and DELETE to exchange data. 
Asynchronous Communication:
Message Brokers (e.g., RabbitMQ, Kafka):
A service sends a message to a broker, which then delivers it to one or more subscribing services. 
Event-Driven Architecture:
Services react to events published by other services, facilitating loose coupling and independent development. 
Other Considerations:
Service Discovery:
Microservices need to know where other services are located, which can be facilitated by using a service discovery mechanism. 
Networking:
Proper networking configuration is essential for enabling communication between microservices, potentially involving a service mesh. 
Authentication and Authorization:
Ensuring secure communication between services requires proper authentication and authorization mechanisms. 
In essence, microservices communicate by exchanging data and requests, either directly (synchronously) or through intermediaries (asynchronously), enabling them to work together to achieve a common goal


22. what is mean by message broker 

A message broker is a software system that acts as an intermediary, facilitating communication between different applications, systems, or services. It receives messages from producers (publishers) and delivers them to consumers (subscribers), potentially routing them or transforming them along the way. This enables loosely coupled, distributed systems to interact without requiring direct connections.
